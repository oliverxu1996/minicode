# MiniCode

[English](README.md) | [简体中文](README.zh-CN.md) | [한국어](README.ko.md) | 日本語

MiniCode は、あなたのリポジトリ内で直接動作するように設計された、明確な方向性を持つコーディングエージェントです。失敗するテストの修正、モジュールのリファクタリング、バグの原因究明——ソフトウェアの作業を MiniCode に任せると、コードを読み、変更を加え、コマンドを実行し、その結果を自身で検証します。その様子はターミナル上でリアルタイムに確認でき、必要ならいつでも方向を指示できます。

MiniCode は意図的に絞り込まれています。汎用の AI アシスタントではなく、ソフトウェア開発の作業を実際に行うためのツールです。

## できること

タスクを与えると、MiniCode は次のことができます。

- 見知らぬリポジトリの探索——ファイルやコードの一覧、検索、調査
- 行番号付き・ページング対応のファイル閲覧、差分で確認できる安全な編集
- 新規ファイルの作成とシェルコマンドの実行（テスト、ビルド、git など何でも）
- 失敗するテストや壊れたビルドへの対応——失敗は情報であり、MiniCode は修復と再検証を繰り返します
- タスクが完了するか、あなたの助けが必要になるまで、自力で複数回のイテレーションを継続
- 実行中のすべての作業を、ターミナル上にライブで表示

典型的なタスクは次のように進みます。

```text
あなた：  このリポジトリで失敗しているテストを修正して。

MiniCode:
  ▸ read src/math.ts
  ✓ read src/math.ts
  ▸ bash bun test math.test.ts
  ✓ bash bun test math.test.ts      ← 失敗を確認
  ▸ edit src/math.ts                ← コードを修復
  ✓ edit src/math.ts
  ▸ bash bun test math.test.ts
  ✓ bash bun test math.test.ts      ← 検証：すべてのテストが通過

  add() 関数を修正しました……すべてのテストが通過しています。
```

主導権は常にあなたにあります。いつでも中断できますし、作業中にメッセージを入力してエージェントの方向を指示することもできます。

## なぜ MiniCode か

コーディングエージェントは、コードに一切手を加える前に、探索と実行——ファイルの読み込み、検索、再読み込み、再試行——に多くの労力を費やします。MiniCode は、このループがうまく機能するように作られています。

- エージェントはリポジトリの「説明」ではなく、実際のリポジトリの状態に対してイテレーションします
- コーディングループは可視化され、操作可能——エージェントの作業を見て、実行中でも方向を変えられます
- 検証はワークフローの一部です。成功を主張するのではなく、テストを実行して変更を証明することが求められます
- コンテキストは意図的に管理され、長いセッションは黙って溢れるのではなく要約されます

MiniCode はソフトウェア開発に集中的に取り組むためのツールであり、汎用 AI アシスタントを目指してはいません。

## クイックスタート

インストール方法は 2 つあり、どちらも同じエージェントが動作します。

### スタンドアロンバイナリ（Linux x86_64）

[リリースページ](https://github.com/oliverxu1996/minicode/releases) から `minicode-linux-x64` をダウンロードします:

```sh
chmod +x minicode-linux-x64
cd ~/my-project
/path/to/minicode-linux-x64
```

このバイナリは自己完結型で、Bun も Node もインストール不要です。現時点でビルド済みバイナリを提供しているのは Linux x86_64 のみです。

### npm

**前提条件:** [Bun](https://bun.sh) がインストール済みで PATH から利用できること。

```sh
npm install -g minicode
cd ~/my-project
minicode
```

初回起動時はモデルが未設定です。`/login` で設定を行い、タスクを入力します。

### ソースから実行

MiniCode 自体を開発する場合はチェックアウトから実行します:

```sh
git clone https://github.com/oliverxu1996/minicode.git
cd minicode
bun install

# プロジェクト内で MiniCode を起動
bun ./packages/agent/src/tui/main.ts /path/to/your/project
```

初回起動時はモデルが未設定です。`/login` で設定を行います——プロトコル（`openai` または `anthropic`）、エンドポイント、プロバイダのモデル名、API キー、トークン上限を順に尋ねられます。設定はローカルに保存され、後から `/model` や Ctrl+P で切り替えられます。

あとはタスクを入力して Enter を押せば、作業が始まります。

## モデルの設定

MiniCode は 2 つのプロトコルを話します。公式 API と、互換性のある任意のエンドポイントの両方で動作します。

| プロトコル | 主な用途 |
| --- | --- |
| `anthropic` | Anthropic API および Anthropic プロトコル互換エンドポイント |
| `openai` | OpenAI API および OpenAI プロトコル互換エンドポイント |

モデル関連のコマンド:

| コマンド | 用途 |
| --- | --- |
| `/login` | モデルを対話的に設定 |
| `/model [id]` | 使用するモデルを切り替え |
| `/logout` | 設定済みモデルを削除 |
| Ctrl+P | 設定済みモデルを順に切り替え |

設定はローカルの設定ディレクトリに保存されます
（`$XDG_CONFIG_HOME/minicode/models.json`、デフォルトは `~/.config/minicode/models.json`）。このファイルを直接編集することもできます。

## エージェントとの作業

タスクの実行中、すべてが見えます。現在のイテレーション、出力のライブプレビュー付きの各ツール呼び出し、ストリーミングされるアシスタントの応答。

- **ステア（Steer）**: エージェントの動作中にメッセージを入力して Enter を押すと、現在の方向を中断して新しい指示に従います。
- **キュー（Queue）**: Alt+Enter でフォローアップを予約できます。現在のタスクの完了後に実行されます。
- **中断**: Esc で実行中のタスクを中止できます。キューに入ったメッセージはエディタに戻されるため、失われません。
- **展開**: Ctrl+O でツール出力の全体表示を切り替えられます。

### セッション

作業内容は自動的に保存されます。終了して後で戻ってきても、`--continue` でワークスペースの最新セッションを再開、`--resume <id>` で特定のセッションを復元、TUI 内の `/resume` で一覧から選択できます。セッションには名前を付け（`/name`）、情報を確認し（`/session`）、以前のメッセージから分岐（`/fork`）、複製（`/clone`）、分岐間の移動（`/tree`）ができます。

タスクの途中で中断された場合は、次回の起動時に中断された作業が自動的に調和されます。完了したステップは保持され、未完了のものは正直に報告され、停止した場所から続行できます。

### スラッシュコマンド

| コマンド | 用途 |
| --- | --- |
| `/help` | コマンド一覧を表示 |
| `/compact` | コンテキストを手動で要約 |
| `/copy` | 直前の応答をクリップボードにコピー |
| `/export [path]` | セッションを JSONL にエクスポート |
| `/import <path>` | JSONL ファイルからセッションをインポート |
| `/name <title>` | 現在のセッションに名前を付けます |
| `/session` | セッションの情報と統計を表示 |
| `/new` · `/resume` · `/fork` · `/clone` · `/tree` | セッションのライフサイクルとナビゲーション |
| `/login` · `/logout` · `/model` | モデル設定 |
| `/trust` · `/reload` | プロジェクトリソース |
| `/hotkeys` | すべてのショートカットを表示 |
| `/quit` | 終了 |

## プロジェクトの指示

MiniCode は、リポジトリのルートにある指示ファイルを読み、作業開始前にプロジェクトの規約を把握します。

- `AGENTS.override.md` — 存在する場合は最優先
- `AGENTS.md`
- `CLAUDE.md`

最初に見つかったファイルがエージェントのシステムプロンプトに読み込まれるため、最初のメッセージからプロジェクトのルールに従って動作します。

さらに、プロジェクトローカルの**プロンプトテンプレート**（`.minicode/prompts/*.md`）と**スキル**（`.minicode/skills/<name>/SKILL.md`）を追加できます。これらのファイルはエージェントの動作を方向づけるため、プロジェクトローカルのものを読み込む前に、`/trust` による信頼の確認を求めます。グローバル設定は `~/.config/minicode/settings.json` にあり、プロジェクトの `.minicode/settings.json` で上書きできます。

## スクリプトと自動化

非対話用途——スクリプト、CI、コードレビューパイプライン向けです。

```sh
# タスクを 1 つ実行し、最終的な応答を表示
minicode -p "このプロジェクトが何をしているか説明して" /path/to/project

# すべてのランタイムイベントを JSON 行として出力（ツール連携用）
minicode --mode json -p "すべての TODO コメントを探して" /path/to/project

# このワークスペースの最新セッションを続行
minicode -c -p "見つけた問題を修正して" /path/to/project
```
